## Rules for this sprint

- **You run every git command.** Claude Code suggests a short commit message after each
  ticket, without the ticket number.
- **Algorithm 2 as written:** every admitted frame gets a frame vector; the clip is the window
  `[t − 2Δ, t]` (the 1 s before the frame), reduced to **8 evenly spaced frames at 224 x 224**;
  both vectors L2-normalised. No frames skipped to keep up.
- **Algorithm 3 as written:** merge by rank, never by raw score; `k0 = 60`; the weights come
  from the classifier.
- **Queries and their correct answers are written and committed before any search is run**
  (OMNI-709). Nothing is tuned on the test queries.
- **One pinned checkpoint per model**, the same locally and on Colab.
- **Only `ai_workers` loads a model.** `query` asks it for text vectors.

## OMNI-703 · Qdrant in the stack, and `frame_vectors`

```
Qdrant collection frame_vectors: size 1152, distance Cosine, HNSW
point id = segments.id
payload {segment_id, video_id, camera_id, source_type, domain, timestamp_s, captured_at,
         frame_path, thumb_path, model, model_revision}
```

- [x] `qdrant` service in `docker-compose.yml`, named volume, **no port published to the
      host**, version pinned; config in `infra/qdrant/`

- [x] `captured_at` is an absolute time for every source: a camera frame's capture time; an
      uploaded file's upload time plus `timestamp_s` (files carry no wall-clock time; recorded
      in `decisions.md`)
- [x] **Payload indexes** on `camera_id`, `video_id` and `captured_at`, so filters run inside

## OMNI-707 · `GET /search`

**Why:** **FR-4** — *natural-language search over stored video, returning a ranked list of the
most relevant moments.*

```http
GET /search?q=&mode=frame|clip|fused&k=5&camera_id=&from=&to=
 -> {results: [{segment_id, video_id, camera, timestamp_s, captured_at, score, matched_by,
                thumb_url}], mode, elapsed_ms, total}
```

- [ ] `query` asks `ai_workers` for the text vector, searches `frame_vectors` (cosine, top `k`,
      `k` 1–50, default 5), joins the hits back to `segments`, `videos` and `cameras`
- [ ] `mode` is in the API from the start: `frame` works today; `clip` and `fused` answer a
      clear "clip index not ready" until OMNI-710 and 711, never a 500
- [ ] **Camera and date filters inside the vector search** (Qdrant filter on the indexed
      payload), never by filtering the top `k` afterwards
- [ ] A hit whose segment no longer exists in Postgres is dropped, counted and logged
- [ ] **Repeated queries:** the text vectors are cached by the exact query text, so a repeated
      query skips encoding (NFR-2 with two searches instead of one). Results are never cached
- [ ] Empty index, empty query, `ai_workers` down: each a distinct, clear response
- [ ] Operator and admin; the token check like every API route (NFR-7)
- [ ] `elapsed_ms` measured inside `query`, split into text encode, vector search, join

**Acceptance:** a query returns ranked moments with every field; a camera filter returns only
that camera's frames even when its best match ranks below other cameras' in an unfiltered

## What to learn this sprint

- [Reciprocal rank fusion](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) — why two
  lists are merged by rank, not by score.
- [InternVideo2](https://arxiv.org/abs/2403.15377) — clip encoders and fixed frame sampling:
  how many frames make a clip, and why the count is fixed.
- [recall@k and honest baselines](https://en.wikipedia.org/wiki/Evaluation_measures_(information_retrieval))
  — a weak baseline makes the lift meaningless.
- [Qdrant: filtering](https://qdrant.tech/documentation/concepts/filtering/) — why a filter
  inside the search beats filtering the top k afterwards.
- [Checkpointing long Colab jobs to Drive](https://colab.research.google.com/notebooks/io.ipynb)
  — sessions die; cached work must not.
